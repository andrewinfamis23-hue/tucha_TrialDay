# Задания

Выполните все три задания. Они взяты из реальных проблем TuchaCRM и ограничены
небольшими изменениями. Для каждого исправления добавьте тест.

## 1. Честный статус корректировки — Junior, до 1 часа

Файл: `addons/tucha_crm/models/request_correction.py`.

После повторного открытия корректировки заявка получает статус `requested`, но
в ней остаются даты получения и проверки прошлого цикла. Из-за этого оператор
видит противоречивую историю.

- При `action_reopen_correction()` очищайте `correction_received_at` и
  `correction_verified_at`.
- Не меняйте дату нового запроса и проверку роли менеджера.
- Добавьте тест: пройти цикл до `verified`, открыть его повторно и проверить
  статус и три даты.

## 2. Безопасный импорт Excel — Middle, 1–1,5 часа

Файл: `addons/tucha_crm/models/request_import.py`.

Сейчас лимит считается приблизительно по Base64-строке. Поэтому фактический
Excel может оказаться больше разрешённых 10 MiB.

- Проверяйте размер декодированного файла.
- Ровно 10 MiB разрешены, 10 MiB + 1 байт отклоняются.
- Повреждённый Base64 должен давать понятную ошибку Odoo.
- Не декодируйте файл повторно.
- Добавьте тесты на границу размера и повреждённые данные.

## 3. Быстрый список заявок — Senior, облегчённое, до 2 часов

Файлы: `addons/tucha_crm/models/request.py` и
`addons/tucha_crm/models/dashboard.py`.

Дашборд регулярно ищет заявки по `planned_from`, но у поля нет индекса, а
условия открытой заявки записаны прямо внутри дашборда.

- Добавьте обычный индекс Odoo для `planned_from` без ручной SQL-миграции.
- Вынесите домен открытых заявок за период в отдельный метод `tucha.request`.
- Используйте этот метод в дашборде, сохранив сортировку `planned_from, id` и
  лимит 8.
- Добавьте тест домена и тест наличия индекса в PostgreSQL.

В PR в 3–5 предложениях объясните, почему индекс ускоряет этот экран и почему
условия открытой заявки лучше хранить в одном месте.

## Сдача

В Pull Request приложите:

- краткое описание трёх исправлений;
- список запущенных тестов и их результат;
- что вы не успели сделать, если работа заняла больше четырёх часов;
- один риск, который проверили бы перед рабочей выкладкой.
