# Задания

Выполните все три задания. Не меняйте публичные имена моделей и существующие
XML-ID. Для каждого исправления добавьте тест.

## 1. Лимит Excel — Junior

Файл: `addons/tucha_crm/models/request_import.py`.

Сейчас размер проверяется по Base64-строке приблизительно. Исправьте проверку:

- декодированный `.xlsx` размером до 10 MiB включительно принимается;
- файл больше лимита хотя бы на один байт отклоняется;
- повреждённый Base64 даёт понятную ошибку Odoo;
- файл не декодируется повторно без необходимости.

Добавьте тесты на границу лимита и ошибочный Base64.

## 2. Быстрая очередь заявок — Middle

Файлы: `addons/tucha_crm/models/request.py`,
`addons/tucha_crm/models/dashboard.py` и новая миграция.

Дашборд часто выбирает открытые заявки по `planned_from` и `stage`, но нужного
индекса нет.

- Добавьте повторяемую SQL-миграцию с частичным составным индексом только для
  открытых заявок.
- Вынесите выборку открытых заявок за период в единый метод модели.
- Сохраните сортировку `planned_from, id` и переданный limit.
- Переведите дашборд на новый метод.
- Добавьте тест поведения и тест определения индекса.

В PR коротко объясните порядок колонок и условие partial index.

## 3. Два оператора берут одну заявку — Senior

Файл: `addons/tucha_crm/models/request_correction.py`.

Две транзакции могут одновременно увидеть свободную заявку и назначить разных
операторов. Устраните гонку средствами PostgreSQL/Odoo.

- Ровно один оператор должен получить свободную заявку.
- Второй оператор должен получить понятную бизнес-ошибку.
- Менеджер по-прежнему может перехватить занятую заявку.
- Пакет записей должен изменяться целиком либо не изменяться совсем.
- Нельзя использовать ручной `commit()` или публичный `sudo()`.
- Добавьте регрессионный тест с двумя независимыми транзакциями.

В PR сравните минимум два варианта блокировки и объясните выбранный.

## Сдача

Приложите к Pull Request:

- краткое описание причины каждой ошибки;
- список выполненных проверок и их результат;
- объяснение миграции и способ отката индекса;
- риски, которые нужно проверить перед рабочей выкладкой.
