# TuchaCRM Trial Day

Локальная учебная CRM для технического собеседования Python/Odoo-разработчика.
Кандидат запускает её на своём компьютере, выполняет три задания и отправляет
результат через Pull Request.

Это не production и не копия рабочей базы. В репозитории нет реальных
клиентов, серверных адресов, SSH-доступа, токенов и скриптов выкладки.

## Что проверяет тестовый день

Задания отличаются не только сложностью, но и форматом работы:

1. **Junior:** дано готовое решение — нужно аккуратно реализовать его и
   написать тест.
2. **Middle:** нужно подготовить подробный `SOLUTION.md`, но не менять код.
3. **Senior, облегчённое:** нужно предложить решение, реализовать его и
   подтвердить тестами.

Полные условия, нужные файлы и пошаговые действия находятся в
[TASKS.md](TASKS.md). Ориентир по времени — 3–4 часа.

## Что находится в песочнице

- Odoo Community 18;
- PostgreSQL 18;
- учебный модуль `addons/tucha_crm`;
- 5 фейковых клиентов;
- 50 фейковых заявок;
- 25 фейковых начислений;
- 20 операций в схеме `wms_mock`;
- две фейковые учётные записи;
- CI с Ruff и `compileall`.

WMS полностью заменён локальным мок-слоем. CRM может читать `wms_mock.*`, но
PostgreSQL запрещает ей `INSERT`, `UPDATE` и `DELETE`.

## Что нужно установить

- Git;
- Docker Desktop либо Docker Engine с Compose v2;
- 4–6 ГБ свободного места для Docker-образов и volumes;
- свободный локальный порт `18069`.

Python, Odoo и PostgreSQL отдельно устанавливать не нужно.

## Первый запуск

```bash
git clone https://github.com/tuchaML/tucha_TrialDay.git
cd tucha_TrialDay
docker compose up --build
```

Первый запуск скачивает официальные образы и создаёт учебную базу. Это может
занять несколько минут. Дождитесь в журнале строки `Registry loaded`, затем
откройте:

<http://127.0.0.1:18069/web/login>

База `tucha_sandbox` выбирается автоматически. Страница менеджера баз отключена
и для работы не нужна.

### Учётная запись кандидата

```text
Логин:  candidate@example.test
Пароль: candidate-sandbox-2026
```

### Учётная запись менеджера

Она нужна для первого задания — повторного открытия корректировки.

```text
Логин:  manager@example.test
Пароль: manager-sandbox-2026
```

Все адреса, пароли и данные в этом разделе учебные и работают только внутри
локальной песочницы.

## Если страница входа не открылась

Проверьте состояние контейнеров:

```bash
docker compose ps
```

Контейнер `db` должен быть `healthy`, а `odoo` — `running`. Затем посмотрите
журнал Odoo:

```bash
docker compose logs -f odoo
```

После строки `Registry loaded` обновите страницу. Если порт занят другой
программой, Docker покажет ошибку `port is already allocated`.

## Остановка и повторный запуск

Остановить контейнеры, сохранив учебные данные:

```bash
docker compose down
```

Запустить снова:

```bash
docker compose up -d
```

Полностью удалить только учебную базу этого Compose-проекта и создать её
заново:

```bash
docker compose down -v
docker compose up -d --build
```

Команда `down -v` удаляет изменения, сделанные кандидатом через интерфейс, но
не удаляет исходный код и Git-коммиты.

## Проверки перед сдачей

Быстрые проверки репозитория:

```bash
ruff check addons tests
python -m compileall -q addons tests
python -m unittest discover -s tests -v
docker compose config -q
```

Для заданий 1 и 3 нужны серверные тесты Odoo. Перед их запуском пересоберите
образ, чтобы контейнер получил изменённый код:

```bash
docker compose build odoo
docker compose stop odoo
docker compose run --rm --no-deps --entrypoint odoo odoo \
  --config=/etc/odoo/odoo.conf --database=tucha_sandbox \
  --update=tucha_crm --test-enable --test-tags /tucha_crm \
  --stop-after-init --no-http
docker compose up -d odoo
```

В задании 2 код и тесты писать не нужно. Результатом должен быть файл
`SOLUTION.md` в корне репозитория.

## Как сдавать работу

1. Сделайте fork репозитория.
2. Создайте ветку `feature/test-day-<фамилия>` от `sandbox-main`.
3. Выполните задания из [TASKS.md](TASKS.md).
4. Запустите проверки.
5. Откройте Pull Request в `sandbox-main` исходного репозитория.
6. Заполните шаблон Pull Request и честно укажите незавершённые пункты.

Не добавляйте в Pull Request `.env`, дампы базы, реальные данные, токены или
адреса рабочих систем.

## Структура репозитория

```text
addons/tucha_crm/   учебный модуль Odoo
docker/             Dockerfile, конфигурация Odoo и фейковый seed PostgreSQL
tests/              быстрые проверки состава и изоляции песочницы
.github/            CI и шаблон Pull Request
compose.yaml        локальные контейнеры Odoo и PostgreSQL
TASKS.md            три задания кандидату
```
